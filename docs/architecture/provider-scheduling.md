# CPA 的 Provider 怎么接单、暂停和恢复

**状态：目标设计，2026-11-21。** 这份文档约定下一版应该怎样工作，不代表功能已上线。文中产品用词以[统一语言词表](../../UBIQUITOUS_LANGUAGE.md)为准。

两个现有页面分别改名：“AI 提供商”→**付费接入管理**，“凭证管理／凭证”→**额度接入管理**。两页管理的共同对象叫**接入**（Provider／上游接入）；凭证只指接入使用的认证材料。额度接入可以是付费订阅，付费接入也可能受额度限制。此次命名只改页面文字：两页保留原有 URL、数据和权限，不合并或迁移；调用方的支付规则仍独立判断。

一笔 `gpt-6.2-sol` 请求进来，订阅 A 要等 135 小时，订阅 B 的令牌已过期，预付费 C 现在能接。如果调用方允许花 C 的钱，CPA 直接用 C，一秒也不为 A 等。如果调用方不许用 C，且 B 没有能在请求预算内完成的恢复机会，就立即告诉客户端「这个模型目前没有可用路线」。后台仍继续查 A 的额度、刷新 B 的凭证。**发给谁、要不要等是当前请求的事；让 A 和 B 恢复是后台的事。**

## 一笔请求怎样走

1. **看全同一模型的路线。** 从配置和模型注册信息列出能映射到请求模型的路线，不先选上游平台。按工具、流式、图像、推理等能力，以及调用方身份、允许的资金来源和明确锁定的 Provider 取得**合格路线**。同名不代表同能力；低优先级不代表禁止花钱。按稳定的 Provider 身份和路线去重；别名、重复注册和凭证轮换不能凭空增加权重或重试次数。未知模型或调用方无权限按入口原有协议报错。
2. **再看谁现在能接。** 对合格路线检查手动许可、自动暂停、认证、冷却、本次请求排除和并发名额。先过滤，再按优先级选择；高优先级都不可用，低优先级可立即接单。同级优先复用健康的会话路线，再按配置的权重或轮询选；同级无绑定请求公平分配，显式顺序填充除外。普通亲和可以打破，身份或会话硬锁不能打破。选路与领取并发名额同时完成；争抢失败先试下一条，完成、取消或失败时释放名额。
3. **有可用路线就发。** 成功即结束。失败先分清是请求本身、这条路线、整个 Provider，还是有证据的共享资源出了问题。把这次尝试记入同一份请求预算，若尚可安全重放，先走下一条未试且可用的路线。同平台与跨平台都服从相同规则；不得通过换 key、别名或地址绕过同一限制。
4. **没有现成路线才考虑等。** 只有明确、可信的恢复机会在剩余等待预算内，而且尚有上游尝试次数、等待后仍来得及执行，才可等到那一刻重新选择。有其他路线提前恢复可提前唤醒；取消则立即结束。仅有“下次例行检查时间”、需人工重登、未知恢复时间或要等 135 小时，都不足以让这笔交互请求挂起。不得把长冷却切成每秒一段反复重选。

## 只有 Core 决定能不能发，只有管理员决定允不允许用

Core 的**请求调度模块**统一负责选路、占位、换路、等待与终止；所有会发起推理的入口都经过它。它对调用方只提供「执行这笔请求」及「解释这笔决定」两种操作；调用方不需要知道余额怎么算、哪一层会重试。上游适配器返回结构化事实、尝试结果和是否已有业务输出，不另开重试循环。模型注册与能力匹配仍由现有模块维护；调度器消费其完整结果及排除原因，不另造一份模型目录。

Manager 后台负责主动查询额度、保存观测、调度复查及展示；凭证刷新任务负责续期并报告结果。**Core 是有效路由状态的唯一写入者**：消费授权的管理命令、后台观测和本次推理的真实反馈；当前请求确认的阻断对下一次选择立即可见，无须等待面板、定时任务或使用量事件。面板只提交手动许可变更或复查请求，不从显示文字推导状态，不回写自动暂停。

管理员只保留「允许使用此 Provider」。对可信证据已确认的耗尽，所有 Provider 自动暂停，没有第二个“参与自动启停”开关。手动停用、额度暂停、认证异常及暂时过载分开保存，可以同时存在；每个恢复动作只解除自己有证据解除的原因。运营侧另设的**低余额保护**也必须使用独立原因，不能把还有余额显示成“已用完”。

## 什么证据能停，什么证据能开

| 看到了什么 | 对后续派单做什么 | 怎样恢复 |
| --- | --- | --- |
| 上游结构化原因明确表示某模型窗口耗尽 | 只暂停该 Provider 的该模型；同一模型在其他 Provider 的路线照常使用 | 同范围新鲜可信观测确认能用 |
| 账户所有适用资金来源都明确不可用，或权威拒绝明确覆盖整个 Provider | 暂停依赖这些来源的路线。套餐与充值两者都能支付时，只空一项不等于整个 Provider 耗尽；多窗口按该产品的真实规则，不相加或猜测 | 任一合法资金来源明确恢复，解除对应暂停 |
| 确认共享钱包耗尽 | 只影响**必须使用该钱包**的路线；仍有独立资金来源的保留。两个 key 同属一家上游平台，不足以合并钱包 | 与同一钱包、币种和身份对应的新证据；无法确认范围时不扩大 |
| 普通 429、5xx、网络失败 | 使用已验证的类别做本次换路或短冷却；没有耗尽证据，不写额度暂停 | 遵守可信限速提示或暂时故障退避；不修改手动许可 |
| 令牌过期或明确认证拒绝 | 对受影响的认证身份停止派单；按原因尝试**凭证刷新**，网络错误不能判为需要重登 | 刷新成功解除认证阻断；明确撤销、刷新令牌失效等才要求重新登录 |
| 额度复查超时、返回旧数据、没有查询权限 | 记为“未知/陈旧”和最近一次成功时间；不能把未知当零，也不能把已确认的暂停抹掉 | 成功取得更新且匹配范围的观测；确实没有查询能力则给管理员具体原因和处理入口 |

采用原始精确数值、单位、受控来源、目标身份、作用范围、观测时间与身份/配置版本。迟到的旧结果、另一账号的余额、同账号其他模型的成功、页面四舍五入的“0.00”，均不能推翻较新的有效阻断。每个阻断保留来源与原因；同一观测重复到达不得重复启停。对没有可靠查询途径的资源，不自动用付费推理探测余额，不凭时间自行开闸。

**额度复查独立于浏览器。** 以全库存每小时复查为基线，已暂停、手动停用、屏幕不可见的 Provider 都在清单内；上游给出重置时刻则到点额外复查，充值后可手动立即复查。三种触发共用同一次在途查询，按来源限速，失败退避；重启合并补查并从已保存的阻断恢复。**135 小时是复查线索。** 第 10 小时的新观测已证明该范围能用，可以提前解除；第 135 小时查询失败仍保留暂停。认证续期独立按令牌有效期提前安排，相同身份同时只刷一次，重复失败在管理端预警，不等下一个请求发现。

## 请求预算与最终返回

整笔请求共用一本账：已试和已排除的路线、各轮实际发给上游的次数、累计主动等待、剩余截止时间、是否已有可见输出或不可重放的副作用。额度查询／凭证续期属于后台，不算一次推理尝试。普通 HTTP、流式初始化、Home 或内部回退不得重置这本账；客户端主动重发才是一笔新请求。

建议交互默认值：**先试一轮合格且可用的未试路线；真实上游暂时失败最多再开一轮；整笔主动等待合计不超过 3 秒**，并遵守每轮的路线尝试上限。数值是待按真实流量验证的起点，不是已有配置。每次等待还受单次冷却等待上限及客户端截止时间约束；正常推理耗时另受上游超时约束。显式 `upstream-error-retry-limit: -1` 只允许对确实已发往上游且可安全恢复的暂时失败继续尝试，仍遵守等待、截止、取消和已排除路线的约束；本地没有可用路线不能进入该分支。配置 `0` 不因换了入口就多开一轮。

已经向客户端交付文本、工具调用，或无法排除重复执行副作用时，不再透明换路或重放。尚未输出但上游可能已执行有副作用的操作，也不能仅凭“没输出”推断安全；需有可验证的幂等保证。HTTP 状态已提交时，用对应流协议的错误事件终止，不再尝试发送第二个 HTTP 状态。

| 最终情况 | 客户端看到什么 |
| --- | --- |
| 参数错误、未知模型、调用方无权使用 | 对应协议的 4xx；例如现有 Core 路由入口对未知模型返回 400 / `model_not_found`。不试遍所有 Provider。某个上游的认证失败不冒充调用方 401 |
| 本地无可用路线：手动停用、额度暂停、凭证过期或混合阻断，且没有预算内恢复路径 | 尽快返回 503 与稳定原因码 `no_available_route`，说明该请求模型暂不可用；不伪造上游 429/504。若一次推理也没发，尝试计数为零 |
| 确实收到上游限流，按其专有规则已无合法备用或预算已尽 | 保留适用的 429 和脱敏类别。例如 #54 的特定 Antigravity 拒绝不转为“整个账号没钱” |
| 真实上游暂时失败耗尽请求预算，或客户端已取消 | 前者按协议返回脱敏的上游失败类别；后者立即停止并释放名额，不再发起调用 |

`Retry-After` 只在有适用于**这笔请求**的、可信且仍有效的正延迟建议时返回，表示建议稍后再试。不把某条路线的重置时刻、后台小时安排或未解决的认证问题冒充为整个模型的恢复时间；混合阻断无可靠建议时省略。客户端拿到模型、稳定类别和关联号；管理端凭关联号可看各阶段的候选数量、归属、全部排除原因、尝试次数、累计等待、最近刷新结果和下次复查。日志和错误均不包含令牌、凭证文件名、邮箱、原始响应或请求内容；鉴权前不暴露 Provider 库存。

## 如何验收、怎样切换

让隔离实例的公开 HTTP 入口连接受控上游，用可控时钟分别断言**客户端结果、每个上游实际调用数、主动等待时间、管理端诊断**。操作管理页面的按钮或看到一行日志都不能替代这些断言。

| 初始条件或事件 | 必须看到的结果 |
| --- | --- |
| A 已暂停；B 同模型可用 | 只调用 B 一次；对 A 零调用、零等待 |
| 订阅 A、B 不可用；另一个上游平台的预付费 C 合格 | 只调用 C 一次，模型、工具、流式和身份约束不变。改为禁止花预付费的钱后 C 零调用，诊断明确归为资格不符，而非余额不足 |
| 只有 A 冷却 135 小时、B 令牌过期；开了 `-1` | HTTP 503，推理尝试数 0，主动等待 0；管理员看见两种原因，客户端拿到脱敏错误；不等 Pi 的 300 秒 |
| 唯一路线短冷却，可信恢复在预算内／外 | 内：只等到该机会再评估；外：不等待。中途取消不再发送。#54 的缺失、0、恰好 3 秒及一次短等后再次失败按窄例外验收 |
| 小时复查、重置到点、充值后立即复查同时发生；旧观测迟到、服务重启 | 同一目标只查一次。新结果只解除同范围原因，失败仍保持暂停；重启和关闭浏览器都不放行手动停用的 Provider |
| 某模型耗尽、已知共享钱包耗尽、身份更换、凭证刷新失败 | 三种作用范围互不污染；旧身份的迟到结果被丢弃。认证失败不改变额度；并发请求不会各自触发续期 |
| 并发抢一个名额、流中断、或工具可能已执行 | 不超发；其他可用路线可接单；输出或不可重放副作用不重复；取消释放名额 |
| 检查声称可提供同模型但没被派单的路线 | 从原始库存到模型映射、资格、手动状态、临时不可用、当轮排除一路可追；可区分未注册、受调用方限制和真正耗尽 |

先离线回放事故，再用相同输入旁路计算新选择：只比较决定，不重复占位、发请求、花钱或写状态。核对健康路线被漏选、误用预付费、零尝试时仍等待、重复恢复及脱敏问题。按模型／调用方小范围切换；任一时刻、同一范围只有一个调度和状态写入者，旧浏览器写入等路径在切换点停写。旧 `disabled` 无法判断归属的保持停用、标记待核实，不直接自动打开。回退时隔离新写入，保留手动意图、已确认阻断及审计，旧实现能正确读取这些状态才接管；无法可靠映射的路线保持暂停。此文档不变更线上配置、既有 Issue 或发布状态。
